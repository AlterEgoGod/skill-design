# Аудит существующего интерфейса

Применяй по запросу проверки или разбора, независимо от трёх режимов выбора оформления. Аудит не запускает начальный опрос и не меняет файлы продукта без запроса исправлений. Не превращай небольшую правку в аудит всего продукта.

1. Зафиксируй область: экран, пользовательскую задачу, версию, темы и доступные состояния. Изучи существующие компоненты и требования бренда.
2. Проверь рабочий сценарий, клавиатуру и фокус, ошибки, загрузку, пустые данные, длинный RU/EN-текст, адаптивность и контраст. Не выполняй реальные отправки, удаления или покупки ради проверки; используй тестовую среду и данные.
3. Для каждого замечания укажи компонент/экран, условие воспроизведения, фактическое и ожидаемое поведение, доказательство, влияние и конкретное исправление. Разделяй измеренное нарушение, наблюдаемую проблему сценария и рекомендацию по вкусу.
4. Приоритеты: P0 — блокировка критичного сценария/потеря данных; P1 — существенная проблема выполнения задачи или доступности; P2 — локальная несогласованность; P3 — необязательная полировка. Приоритет определяется последствиями, а не только числом предупреждений инструмента.
5. Отдельно перечисли ограничения проверки и удачные решения, которые нужно сохранить. Если проблем не найдено, сообщи «не найдено в проверенной области», а не «весь интерфейс соответствует WCAG».
6. Если исправления разрешены, устрани выбранные проблемы, повтори соответствующие проверки и отметь остаточные ограничения. Обнаруженные несвязанные проблемы не исправляй автоматически.

## Необязательный браузерный инструмент

`scripts/audit_ui.py` создаёт скриншоты, JSON-отчёт о горизонтальном переполнении, ошибках страницы и, при переданном axe-core, части проблем доступности. Он проверяет начальное состояние страницы на выбранных ширинах, не выполняет сценарии и не перебирает темы/стилистики автоматически. Поле `axe: null` означает, что axe не запускался, а не что нарушений нет. Незавершённые проверки axe и прочие ошибки считаются ошибкой инструмента.

Используй зависимости проекта; не устанавливай их без необходимости для обычной правки. Если Playwright отсутствует, сообщи об этом и предложи установку по принятому в проекте способу. Пример подготовки отдельного окружения: `python -m pip install playwright`, затем `python -m playwright install chromium`. Скрипт также принимает `--executable` для установленного Chrome. axe-core устанавливается в целевой проект отдельно; передай путь к `node_modules/axe-core/axe.min.js`. Сам скилл не содержит браузера, axe-core или других runtime-библиотек.

```sh
python scripts/audit_ui.py --url http://127.0.0.1:5173 --output ./ui-audit
python scripts/audit_ui.py --url http://127.0.0.1:5173 --output ./ui-audit-dark --theme dark --axe ./node_modules/axe-core/axe.min.js --strict
```

`--theme dark` добавляет на HTML `data-design-theme="dark"` и класс `dark`; это подходит только проектам с таким контрактом. Скрипт не нажимает переключатель приложения; React может переопределить атрибуты. Поэтому всегда проверяй фактический рендер. Для других систем тем адаптируй проверку к проекту.

Коды завершения: 0 — проверка завершена; 1 — в строгом режиме найдены переполнение, ошибка страницы или нарушения axe; 2 — ошибка аргументов, браузера, загрузки, зависимостей или анализа. `incomplete` axe требует ручного разбора и сам по себе не считается подтверждённым нарушением.

Отчёты могут содержать данные страницы; храни их вне публикуемого скилла, не коммить чувствительные скриншоты. Скрипт не принимает cookies и не открывает существующий профиль пользователя. Для закрытых интерфейсов используй тестовый вход в рамках инструментов проекта.

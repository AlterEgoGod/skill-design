# Интеграция с существующим проектом

## Сначала обследование

Прочитай манифест, стили, библиотеку компонентов и её версию. Найди владельцев темы, размеров и состояния. Не создавай второй конкурирующий набор токенов. При узком исправлении используй существующую конфигурацию без переключателей оформления и миграции стека.

## Обычный CSS и React

Подключай только нужные ресурсы: `tokens.css` как стартовую базу, затем `appearance-presets.css`, при необходимости шрифтовые пресеты, skeleton и стекло. Сопоставь переменные с именами проекта. Сами ресурсы не загружают веб-шрифты и не заменяют иконки.

В приложении с самостоятельной темой один корень HTML может хранить `data-design-style`, `data-design-theme`, `data-design-accent` и `data-design-palette`. React должен обновлять согласованную конфигурацию, не сбрасывая независимые выборы. При SSR согласуй серверный и первый клиентский рендер: не читай localStorage во время серверного рендера и не скрывай весь интерфейс до hydration. Поддержи системную тему, но сохраняй приоритет явного выбора пользователя.

Компонент использует роли, например `border-radius: var(--design-radius-control)`, а не собственное постоянное значение. Для круглого аватара осмысленно оставить `50%`. Передавай тот же контекст в portal: атрибуты на HTML наследуются обычными порталами в body, но отдельные документы и Shadow DOM требуют явного сопоставления.

## Tailwind и shadcn/ui

Определи версию Tailwind и формат цветов в текущем проекте. Для Tailwind 4 семантические цвета связываются через `@theme inline`; Tailwind 3 обычно использует `theme.extend`. Не копируй конфигурацию одной версии в другую.

Если библиотека принимает полный CSS-цвет, адаптер может сопоставлять:

```css
/* Только внутри явно выбранного адаптера темы проекта. */
--background: var(--design-canvas);
--foreground: var(--design-text);
--card: var(--design-surface);
--card-foreground: var(--design-text);
--popover: var(--design-surface-overlay);
--popover-foreground: var(--design-text);
--primary: var(--design-accent);
--primary-foreground: var(--design-on-accent);
--muted: var(--design-surface-muted);
--muted-foreground: var(--design-text-muted);
--border: var(--design-border);
--input: var(--design-control-border);
--ring: var(--design-focus);
```

Это пример сопоставления, не готовое универсальное переопределение. Старое `hsl(var(--primary))` требует HSL-каналов и не принимает HEX-переменную напрямую. Проверь также secondary, accent, destructive, состояния и графики; не подменяй их все основным брендовым цветом. Унаследованные переменные вычисляются в контексте их владельца: размещай адаптер на том же корне, что и исходные значения, либо переопределяй их в каждой области темы.

Не присваивай всем радиусам shadcn одно значение без проверки: библиотечные sm/md/lg часто вычисляются из базового радиуса. Проверь фактическую геометрию кнопок, меню и карточек. Если используется готовая дизайн-система с собственными вариантами и контрактами (например ReUI), сохраняй её поставляемые компоненты и используй штатные props и тему; не применяй общие CSS-правила поверх них вслепую. Изменение всей системы оформления требует соответствующего запроса пользователя.

## Проверка интеграции

Проверь computed styles реальных компонентов, открытое меню в portal, диалог, выбранный пункт с hover/focus, текст на акценте, ошибки, обе или все доступные темы, узкий экран и увеличение. Установка пресета сама по себе не подтверждает интеграцию. Прогоняй сборку и подходящие проверки проекта; инструменты скилла их дополняют, а не заменяют.

## Постоянное подключение — по выбору владельца

Не изменяй глобальные инструкции и не создавай AGENTS.md/CLAUDE.md без запроса на такую настройку. По запросу дополни существующий файл коротким правилом, сохраняя его остальные инструкции:

> Для задач создания или изменения интерфейса загружай установленный skill-design. Сохраняй бренд и систему компонентов. После изменений проверяй затронутые состояния, доступность и адаптивность; исправляй внесённые регрессии и сообщай только о реально выполненных проверках. Не применяй это правило к задачам, не затрагивающим интерфейс, и не переделывай несвязанные экраны.

Не заявляй автоматическую активацию, пока она не проверена в конкретной среде. Пути установки и команды зависят от агента и версии; проверяй их при настройке, не удаляй работающую установку из-за общего примера пути.
